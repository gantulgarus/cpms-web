# Хийгдэх ажлын лавлах · 2026-11-16

`Лавлах сан → Ажлын жагсаалт` нь сүүлийн Excel-ийн 293 мөрийг харуулна.
7 бүлэг, дэд бүлгийн дугаар, ажлын төрөл, хийгдэх ажлын нэр, нэгж болон эх файлын
байршил/давхрын тайлбарыг хадгална. Нэгтгэсэн нүдийг зөвхөн Excel-д заасан
хүрээгээр үргэлжлүүлнэ. Эх мөрийн түүхий утга backend-ийн `source_values`-д үлдэнэ.

`WT-000001` кодыг өгөгдлийн сангийн автоматаар олгосон identity-гаас гаргана.
Нэр, нэгж, тодорхойлолт засахад код өөрчлөгдөхгүй. Төсвийн `code/code_part`-оос тусдаа.

Хуучин лавлахын тусдаа таб хасагдсан. Шинэ лавлах цорын ганц үндсэн лавлах байна.
«Хаана хийгдэх вэ» гэсэн давхар багана хасагдсан. Эх файлын байршил, давхар,
ажлын нэрээс барилга/давхар/айлын түвшинг автоматаар гаргана. Мэдээлэл нь
тодорхойгүй, эсвэл хоорондоо зөрчилтэй бол «Байршил тодруулах» тэмдэглэгээтэй
үлдээнэ. Зөвхөн эдгээр мөрийн засах цонхонд нэг удаа түвшин нөхөх сонголт гарна.
Өмнө гараар тодруулсан түвшинг хадгална. Нэгж, байршил тодорхой болсон ажилд
төлөвлөлтийн `WorkType` identity үүсэж, барилгын «Ажил нэмэх» жагсаалтад орно.
Энэ identity нь хоёр дахь лавлах биш; `work_catalog_entries.work_type_id`-аар нэг нэгээр
холбогдох техникийн бичлэг. Дахин засахад ижил identity-г шинэчилнэ. Ажил үүссэн
бол нэгж, байршлын түвшин сервер дээр түгжигдэнэ. Шинэ барилгад бүх ажлыг автоматаар
үүсгэхгүй, төсөв болон хамаарал таамаглахгүй.
Зоорь, тодорхой давхар, давхрын интервалын хүрээг ажил нэмэхэд болон дэлгэцийн
үүсэх мөрийн тооцоонд хэрэглэнэ. 2–16 давхар гэсэн хүрээнд техникийн давхар
орохгүй. Дутуу нэгжтэй ажлыг төлөвлөлтөд холбохгүй.
Эх файлын урьдчилсан/зэрэг хийх ажлын баганууд хоосон тул хамаарал таамаглаагүй.
Тоо хэмжээ 1, үнэ 100, хугацаа, гүйцэтгэгчийг компанийн лавлахын утга болгоогүй.
Excel-ийн 172-р мөрийн “Шахтны нүх бөглөх” ажлын нэгж үнэхээр хоосон;
өөр гурван мөрийн нэгж `0` гэсэн орлуулгатай. Дөрвүүлэнг нь дэлгэцийн
“Нэгж дутуу” шүүлтүүрээр нөхөж болно; `0`-ийг хүчинтэй хэмжих нэгж гэж үзэхгүй.

## Backend байрлуулах

Эх backend нь `../cpms-api`, ажиллах Laravel хуулбар нь `../cpms-api/cpms-api-app`.
Шаардлагатай шинэ model, controller, command, migration, data, test болон route
хоёр байршилд синк хийгдсэн.

Laravel төслийн хавтсаас:

```sh
php artisan migrate --path=database/migrations/2026_11_16_000001_create_work_catalog_entries.php --force
php artisan migrate --path=database/migrations/2026_11_16_000002_link_work_catalog_to_planning.php --force
php artisan migrate --path=database/migrations/2026_11_16_000003_add_catalog_location_resolution.php --force
php artisan migrate --path=database/migrations/2026_11_16_000004_add_work_catalog_soft_deletes.php --force
php artisan cpms:import-work-catalog
php artisan cpms:resolve-catalog-locations
```

Импорт transaction дотор ажиллаж, `source_key`-ээр давхардлыг хаана.
Дахин ажиллуулахад одоо байгаа мөр, түүний гараар зассан утгыг шинэчлэхгүй.
`GET /api/v1/work-catalog` нэвтэрсэн хэрэглэгчид нээлттэй.
`PATCH /api/v1/work-catalog/{id}` нь лавлах удирдах эрх шалгаж нэр, нэгж,
тодорхойлолт, тодорхойгүй байршлын түвшинг засна. Identity болон эх сурвалжийг API-аар солихгүй.
Автомат дүрэм нь `InferWorkLocation` (backend), `infer-work-location.ts` (mock/preview)-д
байна. Барилгын ажлын түвшин нь ажлын нэрээс өөрчлөгдвөл ашиглагдсан ажлын
нэгж, түвшинг түгжих дүрэм үйлчилж, өөрчлөлт бүхэлдээ буцна.

`DELETE /api/v1/work-catalog/{id}` нь лавлах удирдах эрхтэй хэрэглэгчид нээлттэй.
Жагсаалтын хогийн савны товч баталгаажуулах цонх нээнэ. Төлөвлөгөө, загвар,
гэрээ, материалын төсөв эсвэл чанарын хуудастай холбоотой бол сервер 409 буцаана.
Ашиглаагүй ажлын planning identity-г цэвэрлэж, catalog мөрийг soft delete хийнэ.
Эх сурвалжийн түлхүүр, автомат кодыг дахин ашиглахгүй. Импорт `withTrashed()`-аар
шалгах тул устгасан ажил дахин импортод сэргээгдэхгүй. Засах API устгасан мөрийг олохгүй.

## Хуучин тестийн лавлахыг цэвэрлэх

2026-11-16-нд хэрэглэгчийн хүсэлтээр локал орчны 57 хуучин төрөл, 17 хуучин бүлэг,
загварын 148 холбоосыг цэвэрлэсэн. Хуучин төрөл/бүлэгт хамаарах чанарын хуудас
каскадаар арилна. Барилга болон ажлын мөр 0 байсан; шинэ 293 ажил, 7 бүлэг хадгалагдсан.
Цэвэрлэхийн өмнөх лавлахын snapshot `outputs/legacy-reference-before-cleanup.json`-д бий.

```sh
php artisan cpms:retire-legacy-work-reference
php artisan cpms:retire-legacy-work-reference --execute
```

Эхний команд зөвхөн тоолно. Хоёр дахь нь барилга/ажлын мөргүй, шинэ лавлах бүрэн
орсон үед л хуучин, catalog-т холбогдоогүй төрлүүдийг transaction дотор устгана.
FK хязгаарлалтыг унтраахгүй; бусад холбоос хоригловол бүх цэвэрлэгээ буцна.
Шинэ catalog-т холбогдсон төрлүүдийг хадгална. Хуучин DemoSeeder/WorkTypeSeeder,
mock store-ийн өгөгдөл нь regression тестийн fixture хэвээр; одоогийн лавлахын эх
өгөгдөл биш. Цэвэрлэсэн локал орчинд хуучин demo seeder-ийг дахин ажиллуулахгүй.

  дахин импорт, хуучин төрөл болон гараар зассан утгын хадгалалт, API эрх.
- `php artisan test --filter=ReplaceLegacyReferenceTest`: хоосон орчны цэвэрлэгээ,

  тодорхойгүй/зөрчилтэй мөр, давтан тооцоолол, зоорь болон айлын давхрын хүрээ.

  хамгаалалт, холбоогүй planning identity цэвэрлэх, дахин импортод сэргээгдэхгүй байх.
